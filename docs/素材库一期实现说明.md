# 素材库实现说明（Eagle 式 · 一期 + 二期 + 三期，2026-08）

> 一期：缩略图管线、EXIF、评分/描述、字典化标签、智能收藏夹、回收站 + 撤销。
> 二期：以图搜图、相似查重、颜色筛选、截图自动入库、壁纸联动。
> 三期：AI 语义搜索/打标、浏览器剪藏插件、EXIF 地图、字体素材（调研见 docs/素材库三期调研.md）。
> 选型依据：`docs/素材管理竞品调研.md`（Eagle/TagStudio/hydrus 等）。原则：**能开源就不手搓**。

## 1. 开源模块复用表

| 能力 | 选型 | 备注 |
| ---- | ---- | ---- |
| 缩略图 | `sharp` | 256（网格）/ 1024（预览）两级，借鉴 Immich 分级管线；N-API 预编译，Node/Electron 双端免重建 |
| EXIF | `exifr` | 纯 JS、支持 HEIC；字段直接回填既有列（taken_at/相机/参数/GPS） |
| 感知哈希 | `sharp-phash` | 64 位 pHash + distance；对 1024 预览计算保证跨格式确定性；一期只入库，二期做以图搜图/查重 |
| 精确去重 | `js-md5` | 已有依赖；写入既有 `hash` 列 |
| 后台队列 | `p-queue` | 并发 2，onIdle 供测试/收尾 |
| 主色 | `sharp stats.dominant` | 对预览计算，存 `color_dominant`（二期颜色筛选用） |
| HEIC 解码 | 系统 `sips`（macOS）+ nativeImage 兜底 | sharp 预编译不含 HEIC；转换逻辑抽到 `utils/imageConvert.ts` 共用 |
| 智能收藏夹模型 | 借鉴 Eagle 智能文件夹 | rules_json → 参数化 SQL WHERE（`smartAlbumRules.ts` 纯函数） |
| 标签数据模型 | 借鉴 TagStudio | 全局字典 `tag_tags`（color/usage_count 已接入，parent_id 预留） |

## 2. 架构与数据流

```
导入（ipc/photos.ts add/addMultiple）
  └→ PhotoRepository.addPhoto（file_path 唯一，thumb_status=0）
      └→ AssetProcessingService.enqueue（p-queue 并发 2）
          ├→ ThumbnailService.ensure：256/1024 落盘 <userData>/thumbs/<photoId>/
          ├→ exifr.parse（EXIF → taken_at/相机/参数/GPS 列）
          ├→ md5(原文件) → hash 列
          ├→ pHash(1024 预览) → phash 列
          └→ sharp dominant → color_dominant 列
              └→ thumb_status=1；WebContents.send('photos:processing') 推进度
启动恢复：main/index.ts → assetProcessing.recoverPending()（thumb_status != 1 全部重跑）
```

- **协议层**：`thumb://<256|1024>/<photoId>`（`modules/protocols.ts`）命中缓存直返、未命中现场生成；`image://` 保留给预览原图，HEIC 转换逻辑与缩略图共用 `utils/imageConvert.ts`。
- **非侵入式**：图片不复制进应用目录，SQLite 只存引用——与 TagStudio/Billfish 同哲学，用户数据不被绑架。
- **回收站**：沿用全局软删除约定 `deleted_at`；清空时硬删行 + 孤儿 `photo_tags` + 缩略图目录。
- **撤销**：批量删除后 toast（10s）内 `restorePhotos`，复用软删除。

## 4. 二期实现（已落地）

| 功能 | 实现 |

| 以图搜图（找相似） | `db/photoSimilarity.ts` 纯函数：phash 比特串解析为 hi/lo 两个 32 位整数，XOR + popcount 查表算汉明距离；预览「🔍 找相似」→ `similar:<photoId>` 视图按距离升序展示，翻页限于结果集 |

| 截图自动入库 | `ScreenshotService` 保存成功后 `photoRepository.addPhoto(path, { source: 'screenshot' })` + 经 `assetProcessingRef` 引用桥入队处理管线（避免懒加载循环依赖） |
| 壁纸联动 | PhotoPreview「🖼️ 设为壁纸」直接复用壁纸模块 `window.api.setLocalWallpaper(filePath)` |

## 8. 六期实现（2026-09-01，「剩余任务全量清零」轮）

### 实测结论（修正五期假设）

- **sharp（bundled libvips）解不了 PDF/AI**：`sharp.format` 虽列出 magick/pdf，实际解码抛
  "unsupported image format"（预编译包未含 poppler/pdfium）。五期「sharp magick 待实测有戏」
  的乐观假设被推翻。TIFF 实测可用。
- **PDF/AI 缩略图改走 pdfjs-dist（legacy ESM）+ @napi-rs/canvas**：纯 JS + N-API 稳定 ABI，
  Electron main 与 vitest（纯 Node）都能跑；首页渲染 → 复用既有缩略图管线（pHash/主色照常）。
  pdfjs v6 起销毁接口在 loadingTask 上（`doc.destroy` 已移除）。
- **PSD 无纯 JS 合成图解码器**，不支持缩略图：AssetThumb 对 `thumb_status=2` 的 image 类
  显示扩展名徽章兜底卡片（替代裂图）。
- **AI 环境**：onnxruntime-node 1.24.3 的 darwin 仍只有 arm64；新增
  `scripts/check-ai-env.mjs` 自查脚本，换 Apple Silicon 后先跑它再决定是否调优。
- **剪藏插件真机验证（解冻）**：`e2e/extension-real.spec.mjs` 用 playwright chromium 加载
  MV3 扩展全链路通过。踩坑：`electron <file>` 方式启动时 userData 不是包名目录，
  必须从主进程 `app.getPath('userData')` 取；clip-server.json 有残留，需探活不能只看文件。

## 10. 已知边界

- Windows 上的 HEIC：无 sips，走 nativeImage 兜底，系统无 HEIC 编解码器时会标记 `thumb_status=2`（失败可见，不影响其他图片）。
- 网格虚拟滚动未做（`loading="lazy"` + 256px 缩略图已可承载万级库）；如卡顿再上 `useVirtualList`。
- 番茄钟/图片模块以外的测试未受影响：全套 vitest 308 用例通过，typecheck 全绿。
