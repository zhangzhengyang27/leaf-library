## 分期

### M1 · 数据形状 v2（引擎先行）
- `rules_json` v2：`{ match, groups?: [{ match, not?: boolean, rules }], rules }`——**旧形状照读不迁移**（读到无 `groups` 视为单组），写侧才产出新形状。
- `buildSmartAlbumWhere` 改递归编译（组间 AND/OR、组内 AND/OR、组级取反 = NOT(…)）；SQL 生成器加深度/节点数上限（防恶意/手改 JSON 炸查询）。
- 单测：嵌套组合真值表 + 旧规则回归（现存智能夹读回结果不变）+ 上限拒绝。

### M2 · 编辑器条件组 UI
- 组容器（可增删组、组内增删规则）、组内/组间 AND|OR 切换、组级「不满足」取反勾选；实时命中计数（复用现有预览机制，若无可加 debounce 计数 IPC）。
- 旧规则打开自动呈现为单组形状，保存不破坏。

### M3 · 算子补齐（对齐 Eagle 25 种）
- 字符串：开头/结尾/有无内容（SQL 直接有）；**正则**：SQLite 无原生 regexp——两条路（注册 UDF `regexp` vs 查询后 JS 过滤），涉及性能与下推破坏，**需 D-023 决策**后做。
- 数值 between、日期 within(过去 N 天) 等差额逐个补 `OWNED_RULE_KEYS` + 控件 + 引擎。

### M4 · 嵌套智能夹（可选，独立评估）
- `photo_smart_albums` 加 `parent_id`（migration 027）+ 侧栏树形展示 + 求值时子级自动 AND 父级。
- 单独决策点：Eagle 的树形主要服务组织感，Leaf 已有文件夹体系，**可明确不追**——在 D-022 里一并裁决。

## 验收（判别性）

单测真值表（(A AND B) OR NOT(C) 三层）逐格断言；e2e：建三层嵌套规则 → 命中集与手工 SQL 对账 → 旧库规则打开保存后命中集不变 → 取反组边界（空组取反 = 全集）。

## 风险

rules_json 兼容性（读侧永不容错失败）；递归编译的 SQL 注入面（参数化纪律沿用既有 chunk/placeholders 模式）；编辑器复杂度膨胀（SmartAlbumModal 已大，组 UI 抽子组件）。
