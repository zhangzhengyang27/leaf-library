## 勾账 · M3（2026-09-26 落地，D-023/D-024 立案见 docs/DECISIONS.md）

- **基准与裁决（D-023）**：探针 `scripts/_probes/smart-album-regex-bench.mjs`（内存库 5 万行
  photo_photos 合成数据）。真实分页形态（宽行 + ORDER BY + LIMIT 200）下 UDF 下推 9.0–13.7ms
  vs JS 过滤 29.9–30.7ms（慢 2.2–3.4 倍）；20 万行放大到 3.9–5.4 倍——**UDF 下推胜**，
  分页/计数/组合下推全保留。
- **缺口算子（12 键进引擎 + 编辑器）**：`nameBeginsWith` / `nameEndsWith` / `nameRegex` /
  `descriptionEmpty` / `descriptionHasContent` / `widthBetween` / `heightBetween` /
  `fileSizeBetween` / `durationMsBetween` / `importedWithinDays` / `takenWithinDays` /
  `modifiedWithinDays`（键名照既有 camelCase，嵌套组内照常可用，参数化纪律不变）。
  盘点结论：包含/不包含/相等/数值区间/日期区间已有，不重做；颜色黑白档与字型两算子不追。
- **UDF**：`regexp(pattern, value)` 进 `registerSqlFunctions`（生产与测试库同处注册，
  database.ts 零改动）：模式编译缓存 + 非法模式返回 0（纵深防御）；编译期校验单源
  `checkRegexPattern`（@shared）——编辑器行内报错/禁保存与 `buildSmartAlbumWhere` 拒绝同一口径，
  非法正则绝不带病进 SQL。长度闸 256。
- **编辑器**：顶层「更多条件」补 开头/结尾/正则/注释内容/添加 N 天 五控件；组描述表新增 13 行
  （between 双输入带 KB/秒换算、withinDays 单数字、正则行即时校验）。between 四键与拍摄/修改
  within 只进组编辑器（顶层沿用 min/max 对与日期区间），顶层出现经 passthrough 保留并念出来。
- **测试**：引擎 `src/main/db/__tests__/smartAlbumOperators.test.ts` 18 条（逐算子真内存库断言、
  正则特殊字符注入面、非法正则编译期拒绝、UDF 纵深防御、between 脏形状、嵌套组内可用、
  占位符不变量）；编辑器 `SmartAlbumModal.operators.test.ts` 8 条（顶层/组内往返、非法正则
  禁保存、between 双输入与 KB/秒换算、v2 组规则含新键回填不落「暂不支持」）。
- **MCP 安全裁决并案**：原计划挂在 D-023 名下的 `leaf_get_image` 三个安全裁决（token 复用
  ClipServer / original 扩展白名单 + 8MB 上限 / 路径只来自库内登记）按内容量**拆为 D-024**
  单独立案（见 DECISIONS.md 与 `docs/plans/AI看图工作流-实施计划.md` 勾账节）。

## 验收（判别性）

单测真值表（(A AND B) OR NOT(C) 三层）逐格断言；e2e：建三层嵌套规则 → 命中集与手工 SQL 对账 → 旧库规则打开保存后命中集不变 → 取反组边界（空组取反 = 全集）。

## 风险

rules_json 兼容性（读侧永不容错失败）；递归编译的 SQL 注入面（参数化纪律沿用既有 chunk/placeholders 模式）；编辑器复杂度膨胀（SmartAlbumModal 已大，组 UI 抽子组件）。
