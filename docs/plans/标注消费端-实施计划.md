- overlay 同时渲染已有 rect 标注（可点击高亮 ↔ 检查器列表联动）；标注模式下禁用缩放手势冲突（滚轮归缩放，框选用鼠标左键拖拽，需与既有拖拽平移互斥——平移改空格按住或工具切换）。
- 纪律：PhotoPreview 是 2096 行巨石 + 音频播放链刚修稳，外科手术式增补；overlay 逻辑抽独立 composable（照 usePhotoData 拆分范式），可单测坐标系换算。

### M4 · 筛选与搜索
- **筛选维「标注」已落地（2026-09-26，本会话）**：spec 字段 `annotationFilter: 'any' | 'none'`
  （`src/shared/smartAlbumRules.ts`，缺省 = 不限）→ `photos:getPage` 的 filters 下推
  `buildSmartAlbumWhere` 的 `EXISTS / NOT EXISTS (photo_annotations)`；维度注册
  `filterDimensions.ts`（label「标注」，icon `context-menu/ic-filter-item-comment`，defaultPinned
  false），FilterBar 两档取值面板 + isDimActive/clearDim，usePhotoFilters 本地 matchAnnotation
  （相册/智能夹等非分页路径，在场数据按需分块拉取）；智能夹编辑器 select 控件 + rulesToFilters
  回填；回收站语义照标签维（软删素材的标注行保留到硬删，视图 deleted_at 谓词由 getPage 合并）。
- **评估：标注文本并入 photo_fts —— 停下不做**（2026-09-26 评估，读了 014/018/020 与
  photo_fts 触发器现状后下结论）。方案本身（photo_photos 加 `annotation_text` 物化列 +
  photo_annotations 三个维护触发器 + 026 迁移照 018 范式「删触发器→删索引表→带新列重建」）
  链路是清楚的，但有两处命中止损条件：
  1. **迁移要重建大表**：FTS5 不能 ALTER 列，photo_fts 必须整表 DROP/CREATE +
     `rebuild`——把全库所有素材的 file_name/description/ocr_text/doc_text 重新 trigram
     分词一遍。本仓有 33 万行级导入场景的记载（PhotoRepository.addPhotos 注释），这是一次
     启动期的长迁移。
  2. **写入放大**：photo_annotations 的三个触发器要 `UPDATE photo_photos SET
     annotation_text = group_concat(...)`，该 UPDATE 会级联触发 photo_fts_au 对该素材
     **整行五列**做 FTS delete+reinsert（全部文本重分词）。标注是高频用户动作（预览里
     连注多张），每存一条标注 = 一次全素材 re-tokenize。OCR/doc_text 回填本身不打架
     （020 的 UPDATE ocr_text 照常命中 AU 的 OF 列表），这点是干净的。
  3. 附带发现：SEARCH_SCOPE 两个接入点明确（SEARCH_SCOPE_IDS + 主进程 scopeColExpr，
     有 typecheck 穷举兜底），但客户端回退链有洞——scopeHaystack（useAdvancedSearch）按
     Photo 对象拼 haystack，Photo 上没有标注文本（M3 只拉了 count）。勾「标注」范围后
     FTS 下推路径能命中、非分页回退路径恒不命中，正是 searchScopes.ts 里记载过的
     「勾了范围却静默搜不到」（docText 漏配同款）。
  - **替代方案留决策**：独立 `photo_annotations_fts`（external-content 挂 photo_annotations，
    trigram，单 body 列 + 自有 3 触发器），查询侧与 photo_fts 两段 MATCH 并联（经
    photo_id 一跳映射）。不动 photo_fts、零重建、写入只维护自己的 FTS 行——上面 1/2
    都消失；客户端回退缺口仍在，但默认全局搜索（不勾范围）走 FTS 下推可覆盖主路径。
